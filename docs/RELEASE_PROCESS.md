# 참고 · 배포 후보 갱신 절차

새 기능·버그 수정은 내부 개발판에서 먼저 구현·실사용 검증합니다. 이 저장소는 검증한 변경을 일반 사용자용으로 반영하며 자동으로 공개하지 않습니다.

1. 기준 버전/커밋을 UPSTREAM.json에 기록합니다.
2. 필요한 소스를 허용 목록으로 반영합니다. 내부 Git 이력·개인 문서·실제 환경/인증/원음을 복사하지 않습니다.
3. 배포 표시명·ID·파일명·기본 폴더와 단일 SETUP.md의 일반 설치 경로를 유지합니다.
4. 타입·기존 계약·빌드·ZIP·현행 링크·개인 설정 제외를 확인하고 실제/미검증을 STATUS.md에 구분합니다.
5. 설치 ZIP과 SHA256을 갖춘 초안 릴리스를 준비합니다.
6. 내부 실제 사용 결과·일반 설치 검수 후 공개하고 실제 GitHub 다운로드 해시/manifest를 대조합니다. 이전 자산은 덮어쓰지 않습니다.

자동 동기화·공개 cron/CI가 아니며 실제 서버·네트워크·모델·계정 설정을 복사하거나 바꾸지 않습니다.
