# 전사 방식 고르기와 중단된 작업 복구

[처음 화면](../README.md) · [설치·설정 안내](SETUP.md)

## 먼저, 전사와 정리는 다른 단계입니다

- **전사:** 녹음된 말소리를 글로 옮깁니다. 기본 구성에서는 지정한 처리 서버의 **Whisper**라는 음성인식 AI가 맡습니다.
- **정리:** 전사된 글에서 요약·결정사항·할 일을 뽑아 회의록으로 만듭니다. 사용자가 연결한 **온라인 텍스트 AI**가 맡습니다.

아래 선택은 **음성을 글로 옮기는 방식**에 관한 것입니다. 온라인 AI의 요금제나 회의록 형식을 고르는 메뉴가 아닙니다.

## 세 가지 방식 — 처음에는 기본형을 선택하세요

### 1. 기본형: 녹음하면서 약 30초씩 글로 바꾸기

앱 선택명: **터보 · 녹음 중 구간 전사 (약30초)**

‘터보’는 기본 Whisper 음성인식 모델 **`large-v3-turbo`**의 이름입니다. 녹음과 음성인식을 겹쳐 진행하므로, 회의가 끝나기 전부터 처리된 글을 볼 수 있습니다. 지원 서버에서 기본 선택됩니다.

음성이 약 30초 모이면 한 구간을 처리합니다. 문장 중간 절단을 줄이려고 28초 이후 짧은 무음을 우선하고, 최대 30초에서 구간을 닫습니다. **30초는 녹음 분량이지 처리 완료 시간이나 결과 표시 주기가 아닙니다.** 서버 처리시간이 추가되므로 첫 글이 30초 만에 나온다고 보장하지 않습니다.

### 2. 경량형: 서버 부담을 줄이는 작은 모델로 처리하기

앱 선택명: **빠르게 · 녹음 중 전사 / 파일 구간 전사**

‘스몰(`small`)’은 기본형보다 작은 Whisper 모델의 이름입니다. 더 가벼운 처리가 필요한 경우의 선택형이며 인식 정확도가 낮아질 수 있습니다. 이름·숫자·전문용어는 특히 원음과 대조하세요. 실제 속도·정확도는 녹음과 서버에 따라 달라집니다.

서버 담당자가 한국어를 지원하는 다국어 small 모델을 따로 준비해야 선택할 수 있습니다. **사용자가 모델을 모르거나 이 항목이 비활성화되어 있다면 기본형으로 시작하면 됩니다.** 녹음은 30초 이후 무음을 우선하고 최대 45초로 나눕니다. 기본형과 구간 길이도 다릅니다.

### 3. 종료 후 전체 처리: 녹음이 끝난 뒤 한 번에 시작하기

앱 선택명: **정밀하게 · 녹음 종료 후 전체 전사**

녹음 중에는 음성인식을 시작하지 않고, **녹음이 끝난 뒤 전체 원음을 처리**합니다. 중간 결과가 필요 없고 회의 후에 기다려도 될 때 선택합니다.

**기본 설정에서는 기본형과 같은 `large-v3-turbo` 모델과 인식 설정을 사용합니다.** ‘정밀하게’라는 이름이 더 큰 별도 모델로 바뀌거나 항상 더 정확하다는 뜻은 아닙니다. 주된 차이는 **처리를 시작하는 시점과 음성을 나누는 방식**이며, 구간 경계가 달라 전사 결과도 완전히 같지는 않을 수 있습니다. 서버 담당자가 기본 모델을 바꾸면 기본형·전체 처리에 함께 적용됩니다.

| 선택 기준 | 기본형(앱의 ‘터보’) | 경량형(앱의 ‘빠르게’, small) | 종료 후 전체 처리(앱의 ‘정밀하게’) |
| --- | --- | --- | --- |
| 처리를 시작하는 때 | 녹음 중 | 녹음 중 | 녹음 종료 후 |
| 음성인식 모델 | 서버의 기본 모델 | 별도로 준비한 작은 모델 | 기본형과 같은 서버 기본 모델 |
| 종료 버튼을 눌렀을 때 | 완료 부분 재사용, 미처리 부분 마무리 | 완료 부분 재사용, 미처리 부분 마무리 | 전체 음성 처리 시작 |
| 처음 사용하는 분 | **우선 이 방식으로 시험** | 서버 담당자가 준비한 경우 선택 | 녹음 중 결과가 필요 없을 때 선택 |

주소·토큰·노트 폴더·자동 저장 설정은 바꾸지 않습니다. 이전 서버/다른 음성 제공자는 지원하지 않는 구간 모드를 임의로 사용하지 않습니다.

## 종료 버튼을 누르면 처음부터 다시 전사하나요?

**기본형·경량형에서는 아닙니다.** 아래 순서로 마무리합니다.

1. 이미 글로 바꾼 구간은 그대로 재사용합니다.
2. 대기 중인 구간과 마지막 남은 짧은 음성만 마저 글로 바꿉니다.
3. 합쳐진 전체 글을 온라인 AI가 회의록으로 정리·저장합니다.

예를 들어 5분을 녹음했고 앞 4분 30초의 전사가 이미 끝났다면, 남은 30초 분량만 마무리한 뒤 회의록을 정리합니다. **동작 설명용 예시이며 실제 처리속도 측정값이 아닙니다.** 서버가 밀려 있다면 마지막 구간뿐 아니라 앞서 대기하던 구간도 마저 처리합니다.

이때 ‘모델 준비·음성 전사’ 단계가 다시 표시될 수 있습니다. 이는 전체 재시작이 아니라 남은 작업을 처리하는 표시입니다. 반대로 **종료 후 전체 처리**를 골랐거나 **보관 원음 전체 다시 처리**를 선택했다면 전체 음성을 전사합니다.

## 원음과 글은 어떻게 저장되나요?

원음 녹음과 구간 전사를 겹쳐 실행합니다. 전사문은 화면과 `회의녹음/녹음중-전사-….md` 한 문서에 누적합니다. 종료 시 전체 원음을 **한 파일**로 보관하고 **완료된 구간은 재사용**, 대기 중 구간·마지막 꼬리만 처리한 뒤 전체 전사문을 AI로 정리합니다. 전사 속도가 녹음보다 느리면 종료 후에도 기다릴 수 있습니다.

독립 WAV 구간과 복구 정보는 보관함의 숨김 `.meeting-notes-cache`에 둡니다. 전체 원음 보관과 구간 완료를 확인한 뒤 완료된 임시 음성만 정리합니다. 원음·전사문·최종 회의록은 보존하며 원음 파일을 구간 수만큼 늘리지 않습니다.

## 보관 녹음·파일 재처리

보관한 원음 또는 외부 파일을 선택하면 선택한 전사 방식으로 처리합니다. 구간 모드는 파일을 한 번 전송하고 서버가 연속 처리한 부분 결과를 조회합니다. 매번30초를 기다렸다가 보내는 방식이 아닙니다. 보관 원음은 복제하지 않고 새 전사문·회의록은 기존 파일을 덮어쓰지 않습니다.

전체 보관 원음을 다시 처리하는 것은 새 전사 요청입니다. 이전 녹음의 미완료 구간만 이어받으려면 **미완료 구간 전사 → 구간 전사 계속**을 사용합니다.

## 취소·연결 실패·계속하기

- 전사 취소는 해당 서버 작업의 실제 종료를 확인합니다. 녹음 중에는 전사만 멈추고 원음 녹음은 계속됩니다. 원음을 보관하려면 녹음 종료를 누릅니다.
- 완료된 앞 구간·미완료 음성·작업 ID는 보존합니다. 조회 연결이 끊기면 기존 ID부터 확인하며 자동 재업로드하지 않습니다. 확정 실패/취소 구간만 명시적 계속하기에서 다시 접수합니다.
- 이미 다른 작업이 진행 중이면 기다렸다가 계속합니다. 동시 전사를 여러 개 돌리지 않습니다.
- 창을 닫으면 녹음을 종료해 원음을 저장하고 조회를 멈춥니다. 서버 작업은 자동 취소하지 않으며 다음에 계속하기로 확인합니다.
- 구간 저장에 실패하면 앞부분만으로 완료 회의록을 만들지 않습니다. 전체 원음을 선택해 재처리합니다.
- 진행 중 전사문을 직접 편집하면 편집을 덮어쓰지 않도록 자동 갱신을 멈춥니다. 별도 메모를 사용하거나 완료 후 편집하세요.

정상 종료와 앱 강제 종료·전원 손실은 다릅니다. 아직 전체 파일로 저장되지 않은 원음의 완전 복구는 보장하지 않습니다. 회의 중 앱과 녹음 화면을 유지하세요.

## 성능·검증 한계

구간 분할은 처리 시점을 앞당기는 방식이며 CPU 추론 자체를 일정 비율로 빠르게 만드는 기능은 아닙니다. 구간 경계에서 문맥이 나뉠 수 있으므로 숫자·고유명사·전문용어는 원음과 대조합니다. 실제 Zoom·잡음/동시 발화·장시간 회의·모바일·다른 서버에서 같은 품질과 속도를 보장하지 않습니다. [검증 범위](STATUS.md)를 참고하세요.
