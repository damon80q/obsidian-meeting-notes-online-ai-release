# 전사 방식과 복구 · 온라인 AI

## 세 가지 방식

- **터보 · 녹음 중 구간 전사 (약30초):** 기존 large-v3-turbo/정밀 beam을 사용합니다. 28초 이후 짧은 무음에서 분리하고 최대30초에서 닫습니다. 지원 서버에서 기본 선택됩니다.
- **빠르게 · 녹음 중 전사 / 파일 구간 전사:** 별도 다국어 small 모델이 준비된 경우 사용합니다. 녹음은30초 이후 무음 우선·최대45초로 분리합니다.
- **정밀하게 · 녹음 종료 후 전사:** 녹음이 끝난 뒤 전체 원음을 기존 정밀 모델로 처리합니다.

주소·토큰·노트 폴더·자동 저장 설정은 바꾸지 않습니다. 이전 서버/다른 음성 제공자는 지원하지 않는 구간 모드를 임의로 사용하지 않습니다.

## 녹음 중·종료 시

원음 녹음과 구간 전사를 겹쳐 실행합니다. 전사문은 화면과 `회의녹음/녹음중-전사-….md` 한 문서에 누적합니다. 종료 시 전체 원음을 **한 파일**로 보관하고 **완료된 구간은 재사용**, 대기 중 구간·마지막 꼬리만 처리한 뒤 전체 전사문을 AI로 정리합니다. 전사 속도가 녹음보다 느리면 종료 후에도 기다릴 수 있습니다.

독립 WAV 구간과 복구 정보는 보관함의 숨김 `.meeting-notes-cache`에 둡니다. 전체 원음 보관과 구간 완료를 확인한 뒤 완료된 임시 음성만 정리합니다. 원음·전사문·최종 회의록은 보존하며 원음 파일을 구간 수만큼 늘리지 않습니다.

## 보관 녹음·파일 재처리

보관한 원음 또는 외부 파일을 선택하면 선택한 전사 방식으로 처리합니다. 구간 모드는 파일을 한 번 전송하고 서버가 연속 처리한 부분 결과를 조회합니다. 매번30초를 기다렸다가 보내는 방식이 아닙니다. 보관 원음은 복제하지 않고 새 전사문·회의록은 기존 파일을 덮어쓰지 않습니다.

전체 보관 원음을 다시 처리하는 것은 새 전사 요청입니다. 이전 녹음의 미완료 구간만 이어받으려면 **미완료 구간 전사 → 구간 전사 계속**을 사용합니다.

## 취소·연결 실패·계속하기

- 전사 취소는 해당 서버 작업의 실제 종료를 확인합니다. 녹음 중에는 전사만 멈추고 원음 녹음은 계속됩니다. 원음을 보관하려면 녹음 종료를 누릅니다.
- 완료된 앞 구간·미완료 음성·작업 ID는 보존합니다. 조회 연결이 끊기면 기존 ID부터 확인하며 자동 재업로드하지 않습니다. 확정 실패/취소 구간만 명시적 계속하기에서 다시 접수합니다.
- 이미 다른 작업이 진행 중이면 기다렸다가 계속합니다. 동시 전사를 여러 개 돌리지 않습니다.
- 창을 닫으면 녹음을 종료해 원음을 저장하고 조회를 멈춥니다. 서버 작업은 자동 취소하지 않으며 다음에 계속하기로 확인합니다.
- 구간 저장에 실패하면 앞부분만으로 완료 회의록을 만들지 않습니다. 전체 원음을 선택해 재처리합니다.
- 진행 중 전사문을 직접 편집하면 편집을 덮어쓰지 않도록 자동 갱신을 멈춥니다. 별도 메모를 사용하거나 완료 후 편집하세요.

정상 종료와 앱 강제 종료·전원 손실은 다릅니다. 아직 전체 파일로 저장되지 않은 원음의 완전 복구는 보장하지 않습니다. 회의 중 앱과 녹음 화면을 유지하세요.

## 성능·검증 한계

구간 분할은 처리 시점을 앞당기는 방식이며 CPU 추론 자체를 일정 비율로 빠르게 만드는 기능은 아닙니다. 구간 경계에서 문맥이 나뉠 수 있으므로 숫자·고유명사·전문용어는 원음과 대조합니다. 실제 Zoom·잡음/동시 발화·장시간 회의·모바일·다른 서버에서 같은 품질과 속도를 보장하지 않습니다. [검증 범위](STATUS.md)를 참고하세요.
