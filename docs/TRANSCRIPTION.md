## 전사 방식

기본값으로 시작하면 됩니다. 전사는 음성을 글로 옮기는 단계이며, 이후 온라인 AI가 회의록을 정리합니다.

| 앱 선택명 | 처리 방식 |
| --- | --- |
| 터보 · 녹음 중 구간 전사 (약30초) | 기본 모델로 녹음 중 약 30초씩 처리합니다. |
| 빠르게 · 녹음 중 전사 / 파일 구간 전사 | 더 작은 모델로 처리합니다. 서버 담당자의 추가 설정이 필요합니다. |
| 정밀하게 · 녹음 종료 후 전체 전사 | 녹음이 끝난 뒤 전체 음성을 처리합니다. |

터보(`large-v3-turbo`)와 스몰(`small`)은 Whisper 음성인식 모델 이름입니다. 스몰은 서버 부담이 적지만 정확도가 낮아질 수 있습니다. ‘정밀하게’는 기본 방식과 같은 모델·인식 설정을 쓰고, 처리 시점과 구간 분할이 다릅니다.

기본 방식은 28초 이후 무음을 우선해 최대 30초로, 경량 방식은 30초 이후 무음을 우선해 최대 45초로 나눕니다. 구간 길이와 실제 처리시간은 다르며 속도·정확도는 음성과 서버 환경에 따라 달라집니다. [서버 설정](CONFIGURATION.md)

## 녹음 종료

녹음 중 전사하는 방식에서는 완료 구간을 재사용하고, 대기 중인 구간과 마지막 남은 음성만 처리합니다. 이어서 전체 전사문을 온라인 AI가 회의록으로 정리합니다. 서버 처리가 밀리면 종료 후에도 기다릴 수 있습니다.

‘모델 준비·음성 전사’가 다시 표시되더라도 처음부터 재시작하는 것은 아닙니다. ‘녹음 종료 후 전체 전사’나 ‘보관 원음 전체 다시 처리’를 선택했을 때는 전체 음성을 처리합니다.

## 저장과 복구

전체 원음은 한 파일로 보관합니다. 녹음 중 전사문은 화면과 `회의녹음/녹음중-전사-….md`에 누적하고, 최종 회의록을 별도로 저장합니다.

구간 음성과 복구 정보는 보관함의 숨김 폴더 `.meeting-notes-cache`에 둡니다. 전체 원음 보관과 구간 완료를 확인한 뒤 완료된 임시 음성만 정리하며, 원음·전사문·회의록은 보존합니다.

- **중단된 작업:** ‘미완료 구간 전사 → 구간 전사 계속’을 선택합니다. 기존 작업 ID를 먼저 확인하고, 실패·취소가 확정된 구간만 다시 접수합니다.
- **전사 취소:** 서버 작업 종료를 확인합니다. 녹음 중이면 전사만 멈추고 녹음은 계속되므로, 원음을 보관하려면 녹음 종료를 누릅니다.
- **연결 끊김:** 음성을 자동 재전송하지 않습니다. 기존 작업 상태를 확인한 뒤 계속합니다.
- **창 닫기:** 녹음을 종료해 원음을 저장하고 조회를 멈춥니다. 서버 작업은 자동 취소하지 않으며 다음에 계속하기로 확인합니다.
- **구간 저장 실패:** 앞부분만으로 완료 회의록을 만들지 않습니다. 보관 원음을 선택해 재처리합니다.
- **전사문 직접 편집:** 편집 내용을 보호하려고 자동 갱신을 멈춥니다. 처리 중에는 별도 메모를 사용하거나 완료 후 편집하세요.

전사는 한 번에 한 작업씩 처리합니다. 앱 강제 종료·전원 손실로 아직 저장되지 않은 원음은 완전 복구를 보장하지 않습니다.

## 보관 파일 다시 처리

보관한 원음이나 외부 음성 파일을 선택해 전사·정리할 수 있습니다. 구간 방식은 파일을 한 번 전송하고 부분 결과를 조회합니다. 보관 원음은 복제하지 않고 새 전사문·회의록은 기존 파일을 덮어쓰지 않습니다.

전체 원음을 다시 처리하는 것은 새 전사 요청입니다. 남은 구간만 마무리하려면 ‘구간 전사 계속’을 사용합니다.

실제 Zoom·장시간 회의·모바일 등 환경별 확인 범위는 [검증 범위](STATUS.md)에 정리했습니다.
