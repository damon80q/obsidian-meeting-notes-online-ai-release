# 참고 · 오류 해결 · 온라인 AI

주 설치 순서는 [SETUP.md](SETUP.md)입니다. 오류가 생긴 경우 이 문서를 봅니다.

## 연결·포트

서버의 http://127.0.0.1:8789/health와 사용자 기기의 서비스 주소 뒤 /health를 확인합니다. 플러그인 주소에는 /health를 붙이지 않습니다. Whisper 상태는 http://127.0.0.1:8790/health에서도 확인합니다.

EADDRINUSE는 포트가 이미 사용 중이라는 뜻입니다. Linux는 ss -ltnp, macOS는 lsof로 해당 앱을 확인합니다. 서버를 중복 실행하거나 모든 node/Python을 종료하지 않습니다.

## 401

플러그인 값이 서버 .env의 SERVER_TOKEN과 같은지 확인합니다. AI 키·OAuth를 대신 넣지 않습니다.

## 502/504

입구 서버에 연결됐지만 내부 처리 실패/시간 제한이 발생한 것입니다. Whisper 로딩·파일 크기/형식·AI 연결을 순서대로 확인합니다. 다른 앱에서 띄운 서버가 작업용 프록시 환경을 상속했다면 정상 사용자 환경이나 운영체제 서비스로 다시 실행합니다. 다른 앱의 전역 프록시·로그인을 임의로 끄지 않습니다.

파일은 자동 재전송하지 않습니다. 보관한 원음으로 선택 재시도하고 실패 시 확보한 전사문을 보존합니다.

## Python·오디오 라이브러리

프로젝트 .venv에서 `pip install -r server/requirements.txt`를 실행합니다. 목록에 requests와 faster-whisper1.1.1에 호환되는 av18.1.0 제약이 있습니다. 다른 프로젝트 Python 환경은 바꾸지 않습니다.

## AI 연결

.env의 CODEX_HOME이 로그인 경로와 같은지, CODEX_MODEL이 해당 계정에서 실제 제공되는지 확인합니다. 로그인 상태와 실제 분석 성공은 별도이며 지원되지 않는 모델로 자동 대체하지 않습니다.

## 녹음 종료 후 다시 전사하는 것처럼 보임

터보 구간/빠른 모드는 완료한 구간을 재사용합니다. 대기 중 구간과 마지막 꼬리를 처리할 때 모델 준비·전사 단계가 다시 나타날 수 있습니다. 종료 후 전체 전사를 선택했거나 보관 원음 전체를 다시 처리하면 전체 음성을 전사합니다.

## 429·작업 중단·연결 끊김

전사는 동시1건입니다. 기존 작업을 확인하고 필요할 때 해당 작업의 **전사 취소**를 사용합니다. 다른 사용자의 작업을 종료하지 않습니다. 창 닫기는 조회 종료이지 서버 작업 취소가 아닙니다.

작업 ID가 있으면 먼저 그 상태를 조회하고 자동으로 같은 음성을 다시 보내지 않습니다. 녹음 종료 후 미완료 구간 전사에서 **구간 전사 계속**을 선택합니다. 서버 재시작으로 중단된 작업도 자동 재실행하지 않습니다. 완료한 앞부분과 원음은 보존합니다. 자세한 기준은 [전사 방식과 복구](TRANSCRIPTION.md)를 봅니다.

## 새 전사 모드가 보이지 않음

서버 코드도 함께 업데이트했는지, Node와 Python을 모두 재시작했는지 확인합니다. `/health`만 성공한다고 새 작업 경로가 준비된 것은 아닙니다. 빠르게 모드는 별도 `WHISPER_FAST_MODEL`이 준비된 경우에만 나타납니다.

## 컴퓨터 소리 녹음 실패

데스크톱 OS의 마이크·화면 및 시스템 오디오 권한, 공유 화면의 오디오 옵션을 확인합니다. 컴퓨터 소리 입력이 없으면 녹음 시작을 실패로 알리며 마이크만으로 자동 전환하지 않습니다. 지원되지 않는 환경은 마이크만 녹음하거나 별도 녹음 파일을 선택하세요. 실제 Zoom·장치별 호환성은 별도 시험이 필요합니다.
